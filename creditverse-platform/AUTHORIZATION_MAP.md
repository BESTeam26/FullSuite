## The bypass surface — SECURITY DEFINER functions callable from the API

A DEFINER function runs as its owner, so row-level security does not narrow
what it reads. These 202 are reachable by a signed-in caller (or by `anon`),
which makes each one a place where authorization has to be checked in the
body. **A DEFINER function must never call an RLS-dependent INVOKER helper**
— the helper would answer for the owner, not the caller.

## Views

A view without `security_invoker` runs as its OWNER, so it does not apply the
reader's policies to the tables underneath. That only matters where the API
can read the view, so the column that decides whether a `NO` is a finding is
the last one.

> **1 view readable through the API WITHOUT `security_invoker`.**
> Everything protecting the rows is then whatever the view's own `WHERE`
> clause says — there is no policy underneath to catch an edit that
> weakens it. Each one is a deliberate decision or a defect; check it.
>
> - `borrower_funding_files` — readable by authenticated
